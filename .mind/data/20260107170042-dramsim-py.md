## Explanations

### IssueCommand

- takes a command (const)
- if it's a read command, check the pending read queue for reads from the same
  address
  - service all of those at the same time
  - append to return queue
- for writes, ensure that there are no duplicate writes to the same location in
  the pending writes
  - calculate time between write transaction creation and termination time

# Implementation Idea

- give each channel a PIM queue
- add transactions to PIM queue when provided
- when PIM queue is not empty, try to issue pim commands first
  - (consider enabling PIM mode manually)
  - by setting each channel-level controller to PIM mode
- modify issue to loop through all commands and issue to non-busy banks
  - loop through channel states
    - bank_states_ is a private variable
  - if bank is not busy (call WillAcceptCommand), then...
  - send it the first found command in the pimcmd queue
    - track which banks in channel have received a PIM command this cycle with a
      3d vector
    - NOT done by appending to pending w/r q
    - getreadycommand has to be modified because it checks rank-level activation readiness
        - test and see if it works properly
